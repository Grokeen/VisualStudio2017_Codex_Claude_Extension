## 요청의 적용 범위

현재 TASK025 candidate7의 최종 검사·감사 마감을 우선한다. 아래 P1 기능은 다음 주기 후보이며 현재 동결 소스를 바로 변경하라는 요청이 아니다. 사용자 원문과 감사 지시를 변경하지 않는다. 원본 보고서·설치 자료·과거 실패 근거를 보존한다.

## DR01 공개 버전과 설치 안내 일치

**우선순위 P0, 연구 항목 G01.** README 첫 부분은 v0.9.0과 해당 VSIX를 가리키지만 설치 단계에는 새 ‘계정 로그인 화면’·모델 메뉴·원형 돋보기와 Markdown 작성기를 설명한다. 소스 manifest는 이미0.10.0이다. 문서와 다운로드가 다른 상태로 공개되면 사용자가 설치 후 기능을 찾지 못할 수 있다.

요청: 현재 통합 마감에서 README·사용 안내·버전별 패키지·그림의 버전을 함께 정리한다. 기존 v0.9 링크를 유지하는 동안에는 후보 기능의 상태·적용 버전을 구분하고, v0.10 공개가 끝나면 최종 버전으로 일치시킨다. 문서 담당자의 기존 소유권과 맞춰 처리한다.

완료 조건:

- 공개 README의 설치 링크3개가 안내하는 버전·SKU와 실제 VSIX manifest가 일치한다.
- 새 설치 사용자가 계정 연결·요청 작성·변경 비교 경로를 안내대로 따라갈 수 있다.
- 실제 계정 실행 캡처와 합성·도식 예제는 구분한다.
- 후보의 검사 통과와 공개 배포 완료를 같은 상태로 기재하지 않는다.

## DR02 연결 진단과 로컬 진단 내보내기

**우선순위 P1, 연구 항목 G03.** 현재 NativeCliDiscovery·CliAccountService·ProviderRuntimeService와 계정 창을 재사용한다. 별도 인증 시스템이나 원격 수집기를 새로 만드는 요청이 아니다.

요청: ‘CLI 발견 → 지원 버전 → 계정 상태 → 모델 조회’를 한곳에서 읽고 각 실패의 다음 행동을 선택할 수 있게 한다. 결과 복사 또는 로컬 JSON 저장을 제공하되 기본 진단은 추론 요청을 보내지 않는다.

완료 조건:

- 미설치·명시 경로 오류·미인증·시간초과·미지원 버전·모델 조회 실패를 별도 상태로 표시한다.
- 발견·로그인 창 열기·계정 확인·실제 응답 성공을 구분한다.
- 예: `C:\Users\홍길동\...`과 계정·토큰·연결 문자열·프롬프트·소스가 진단 결과에 그대로 포함되지 않는다. 필요한 경로는 사용자명 제거·축약 처리한다.
- 진단은 `실제 요청 미실행`으로 표시하고, 실제 모델 시험은 별도 명시 행동으로 둔다.
- 제공자 전환·취소·늦게 도착한 이전 응답이 현재 상태를 덮지 않는다.

## DR03 레거시 프로젝트 조건 문맥 보강

**우선순위 P1, 연구 항목 G04.** Capture는 현재 Language·File type·Project·TargetFrameworkMoniker를 읽는다. 이 기존 기능을 재개발하지 않는다.

요청: 가능한 프로젝트에서 LangVersion·PlatformToolset·대상 SDK·활성 구성과 플랫폼을 추가로 확인하고 전송 전 요약에 표시한다. 설정을 읽을 수 없거나 프로젝트가 없는 경우에는 미확인으로 남긴다. 사용자가 선택한 범위 외에 전체 파일·MSBuild import·환경 변수·비밀 설정을 무차별 수집하지 않는다.

완료 조건:

- VS2017·2019의 구형 .NET/C#와 C++ 샘플에서 확인한 조건이 정확히 전달된다.
- 최신 문법·API로 임의 상향하라는 기본 지침이 생기지 않는다.
- 솔루션이 없거나 프로젝트 시스템이 다를 때 예외로 요청 흐름이 중단되지 않는다.
- 기존 읽기 전용 판정·선택 UTF-16 위치·버퍼/디스크 충돌 검증을 유지한다.

## DR04 선택 코드와 빌드 오류에서 요청 시작

**우선순위 P1, 연구 항목 G05.** 네이티브 에이전트의 명령·빌드 능력은 이미 있다. IDE에서 문제와 문맥을 가져오는 진입을 개선하는 요청이다.

요청: 편집기 선택 코드의 ‘설명/수정’과 선택한 빌드 오류의 ‘AI에게 해결 요청’ 진입을 제공한다. 기존 AI Assistant 창·전송 흐름을 재사용한다. 창을 열었다는 이유만으로 유료 요청을 전송하거나 파일을 바꾸지 않는다.

완료 조건:

- 선택한 오류의 코드·설명·파일·행과 해당 버퍼를 확인할 수 있다. 오류가0개이거나 원본 파일이 없는 경우도 처리한다.
- 초기 요청 내용을 사용자가 검토·수정할 수 있다.
- 설명 동작과 수정 동작의 의도를 구분한다.
- 실제 빌드·테스트 결과가 없으면 성공했다고 표시하지 않는다. 선택한 기존 도구와 실행 권한을 따른다.
