## 독립 검토에서 확인한 문제

**SC024-01 / UI 자원 사용 경계:** 닫히지 않은 inline backtick을 연속 입력하면 각 위치에서 남은 기호 구간을 다시 세고 검색해 O(N²) 작업을 수행했다. 문자열·노드·정규식 시간 한도가 있어도 이 scanner 경로에는 계산량 한도가 적용되지 않았다.

고정된 소스 DLL을 별도 프로세스에서 작은 입력 1024/2048/4096으로 각 3회 검사했다. 대표 렌더 시간은 약 2.6/9.9/34ms였고 세 입력 모두 원문과 선택 텍스트를 보존했다. 각 프로세스의 10초 제한에 걸린 경우는 없었다. 계산상 문자 방문 수와 실측 시간을 구분해 기록했고 큰 입력으로 UI를 멈추는 실험은 하지 않았다. 코드 실행·정보 유출 결함으로 분류하지 않았다.

실패한 기호 구간을 한 번에 평문으로 소비하고, 중첩 괄호·닫히지 않은 꺾쇠 검색을 포함한 문서 전체 scan-work 예산 **8,388,608**을 추가했다. 검색은 실행 전에 최악 비교량을 차감하고 직접 순회와 재귀 입력도 함께 계수한다. 원문은 바꾸지 않으며 미리보기 한도에 도달하면 생략 안내를 표시한다.

수정 후 소스 회귀 **78/78**이 10초 부모 제한 내에서 통과했다. 원본 CLI 안내 11,278자는 계산량 24,714, 예산의 약 0.295%로 생략 없이 표시됐다. 보수적으로 계수하므로 문법이 지나치게 밀집된 유효 문서도 미리보기가 먼저 생략될 수 있다. 편집·원문 복사의 전문은 유지한다. **candidate3 DLL의 Markdown78/78, 감사 보완을 포함한 candidate4 DLL의 Markdown82/82에서도 SC024-01 회귀가 통과했다.** 최초 수정 Renderer SHA는 `540A2A6404DB7172EAB872F243781AEB9F25BD6816524DCB012037764DEEF09B`이며 `markdown-freeze3.json`, `markdown-quality-freeze3.json`에 연결한다. C4 Renderer SHA는 `4CF30E1216817786356A9AEDC6B56D748C01B143A8245FDD5FDB43331294B42E`이며 TASK025의 문서 상대 링크 문맥·제한된 코드 토큰 강조 보완이 포함된다.

근거: `artifacts/task024/independent-security-review.md`, `private/security-inline-probe/evidence.json`. 첫 결과와 수정 전 DLL을 보존했다.
