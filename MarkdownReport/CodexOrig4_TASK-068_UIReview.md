## 확인 결과

- 원문 #15의 자동/밝게/어둡게 설정은 현재 `AssistantControl.xaml`의 “자동 · Visual Studio 우선 / 밝게 / 어둡게” 선택과 `AssistantPalette`의 공용 DynamicResource 팔레트로 구현되어 있다. 밝은 모드와 어두운 모드에서 같은 역할의 표면·경계·전경·강조 색 토큰을 사용한다. 기존 TASK054/C12 보고서에는 #15 테마와 통합된 IDE 테마 적용 결과가 기록돼 있다. 이 요청은 새 UI를 중복 추가할 항목이 아니라 회귀 기준으로 유지한다.
- 12:47 #3은 현재 Code 구현이 폭 460px 미만, 목록 표시 상태, 선택된 대화 항목의 더블클릭에서만 목록을 접는다. 넓은 모드와 다른 대화 항목 선택 동작을 바꾸지 않는 점은 기존 반응형 패턴과 맞는다. 목록 접은 뒤 키보드 포커스가 숨겨진 목록 컨테이너에 남지 않고 대화 본문 또는 입력란으로 이동하는지는 통합 후보에서 확인할 항목이다.
- 12:47 #4의 제품 구현은 선택 버튼을 눌러 기존 요청 입력란에 초안을 넣고, 사용자가 검토 후 공통 보내기 동작을 실행하는 구조다. 이는 자동 제출 경계를 유지하면서 기존 입력·전송 UI와 통일한다. 기존 `SurfaceButton` 토큰을 재사용하고 좁은 폭에서는 각 선택지를 한 줄 전체 버튼으로 쌓으면 읽기와 터치/키보드 선택이 더 안정적이다. 현재 XAML은 `WrapPanel`이므로 좁은 폭에서 여러 열로 갈라질 수 있고, 긴 한국어 라벨의 줄바꿈·포커스 순서는 실제 통합 화면에서 확인해야 한다.
- 세 번째 감사의 R3-03은 Markdown 작성/미리보기 기능 범위 차이이며, 테마 #15와 다른 작업이다. 감사의 사용자 안내 및 지원 범위 지시는 유지하고 별도 기능 범위를 #3/#4 UI 수정과 합치지 않는다.

## 통합 후보 수용 기준

1. 다크/라이트에서 공용 팔레트 토큰을 유지하고 버튼, 카드, 링크, 포커스 표시의 대비와 시각적 계층을 확인한다.
2. 320/380/459/460px에서 선택 라벨이 가로 스크롤 없이 줄바꿈되고, 한 줄 버튼 배치와 보내기 툴바가 겹치지 않는지 확인한다.
3. 선택지는 마우스와 Tab/Enter/Space 키로 입력란에 넣을 수 있고, 초안 검토 후 기존 전송 버튼 또는 Enter로 사용자가 직접 보낸다. 초안 삽입과 요청 실행을 혼동시키는 별도 자동 제출 상태는 추가하지 않는다.
4. 좁은 폭에서 목록의 활성 대화 더블클릭은 접기, 단일 선택은 대화 전환으로 구분된다. 접은 뒤 포커스가 보이는 대화/입력 컨트롤로 이동하며 목록 토글로 다시 열 수 있는지 확인한다.
5. 실제 최종 후보에서 키보드 포커스, 스크린리더 이름, 화면 배율 100–200%, 긴 한국어 선택지를 검증한다. 본 설계 렌더는 구현 및 접근성 검증을 대신하지 않는다.
