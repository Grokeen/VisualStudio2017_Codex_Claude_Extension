# TASK-036 — VS2017 15.7.1 전용 패키지와 설치 진단

고객이 알려 준 Visual Studio Professional 2017 **15.7.1**은 기존 v0.11.0 패키지의 최소 버전 15.9보다 낮다. 사용자는 업데이트가 불가능하므로 여러 버전으로 제작하도록 요청했다. v0.11.1에서는 **VS2017 15.7·15.8용, 15.9 이상용, VS2019용, VS2022 x64용** 네 패키지를 제공한다. Community 대상은 상위 SKU에도 적용되므로 Professional 자체를 실패 원인으로 판단하지 않았다.

## 변경 내용

- `scripts/Sync-VsixTargets.ps1`이 `src/VS2017.Legacy.AIAssistant`를 공통 소스 링크로 생성한다. 런타임 참조는 **Shell 15.7.27703·Threading 15.6.31**, 매니페스트는 `[15.0.27703.0,16.0)`이다. 일반 VS2017의 15.9 SDK와 하한은 유지한다. 두 패키지는 같은 확장 ID이며, 설치 도구가 15.7·15.8에 구버전용을 선택하고 15.9 이상에 일반용을 선택한다.
- 구형 BuildTools 15.7 패커의 AvalonEdit/WebView2 관리 DLL 누락을 실제 IDE에서 발견했다. **빌드 전용** 패커를 15.9.3032로 통일하고 런타임 SDK는 15.7을 유지했다. C16 실패를 보존하고 C17을 새로 동결했다. 구 Threading의 중복 AsyncUsageAnalyzers 이벤트 진단만 현대 VSTHRD100 검사와 기존 이벤트 주석으로 대체한다. IDE 제공 SDK DLL은 동봉하지 않는다.
- `scripts/Install-AIAssistant.ps1`과 `InstallAIAssistant.bat`가 IDE 버전·SKU 상속·실제 PE 아키텍처·완전 설치·CoreEditor 존재·패키지 SHA256/실제 ID/버전을 확인한다. 기본 PowerShell 호출은 진단만 수행하고, BAT 또는 `-Install`에서만 선택한 IDE의 공식 VSIXInstaller를 연다. 최종 의존성 검사는 공식 설치기가 수행한다.
- 구형 vswhere에 없는 `-utf8`을 사용하지 않고 호출 중 콘솔 인코딩을 복원한다. 명시된 패키지 폴더가 잘못되어도 다른 폴더로 조용히 전환하지 않는다. 한글·공백 경로, 잘못된 연도 파일, 손상 파일, 기존 진단 파일 보호를 검사했다. 설치 JSON/로그는 자동 전송하지 않으며 Visual Studio 자체를 업데이트하지 않는다.
- README·사용/개발 안내·설치 문제 해결 문서·최상위 테스트 실행기를 v0.11.1에 연결했다. 설치 ZIP에는 네 VSIX, 설치 도구, 안내와 원본 CLI 설치 자료를 포함한다. 기존 v0.11.0 자산은 덮어쓰지 않는다.

## 검증

C16 Legacy의 실제 IDE AvalonEdit 누락 실패와 전체14/16, C17 최초 전체15/16의 검사 도구 불일치, PS5 패커 준비 중 부분 ZIP을 별도 경로에 보존했다. 수정한 C17 패키지를 실제 IDE에서 로드한 DLL SHA와 VSIX SHA를 대조했다. 사용자 일반 IDE 프로필을 자동 교체하지 않고 전용 RootSuffix만 사용했다.

## 독립 감사와 한계

사용자의 기존 지정에 따라 구현 약90%에서 CodexOrig2에 **TASK-037** 독립 감사를 요청했다. [감사 보고](CodexOrig2_TASK-037_Audit.md)에서 선택기40·격리CLI15·공통payload43·ZIP31의 직접 검증과 실제 고객 환경의 미검증 범위를 구분한다. ZIP README 경로 지적은 저장소용 README를 오인한 감사 입력 대조 오류로 동일 ZIP 원문 확인 후 철회했으며 제품·ZIP 변경 없이 정정 기록을 보존했다. 감사 종료와 소유 반납 확인 후 배포한다.

**고객의 실제 VS2017 15.7.1 Professional 설치·실행은 이 개발 PC에서 수행하지 못했다.** 구 SDK 컴파일, SDK DLL 경계 검사, 동일 패키지의 실제 VS2017 15.9 호스트 통과는 그 환경의 성공을 보증하지 않는다. 고객에게는 업데이트 없이 15.7 전용 파일을 제공하고, 문제가 계속되면 진단 JSON·설치 로그로 후속 확인한다. 실제 Claude 계정과 운영 DB/TFVC/운영 배포는 이번 검사 범위가 아니다.

배포 URL·태그 대상 커밋·공개 다운로드 바이트/SHA 확인은 `CodexOrig_TASK-036_Deployment.json`에 별도로 마감한다.
