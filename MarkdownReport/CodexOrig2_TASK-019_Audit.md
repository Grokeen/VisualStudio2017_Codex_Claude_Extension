## 1. 감사 의견

**판정: 일부 반영 — Role.md 전체 요구가 완료됐다고 판정할 수 없다.**

VS2017에서 사용하는 대화·소스 수정·첨부·Markdown 저장과 최신 화면 개선은 대부분 구현되어 있다. 특히 드롭다운, 생각 강도 게이지, A~Z 이름, 안내 카드, 부채꼴 메뉴, 설정 목차와 툴팁은 소스와 실행 검사를 통해 반영을 확인했다.

그러나 **VS2019·2022용 확장 지원이 없고**, 라이선스 안내 배치는 IDE를 실행하지 않는 빌드 경로만 제공한다. 상단 `Chat` 제거도 본문에는 반영됐지만 IDE 탭 제목에는 남아 있다. 또한 독립 전체 검사에서 **12/14묶음 통과** 후, 실패한 두 묶음의 개별 재실행은 통과해 검증 재현성에 미해결 사항이 있다.

이는 v0.8.0의 모든 기능이 실패했다는 판정이 아니다. 현재 구현·검증 범위와 Role.md의 전체 요구 사이에 남은 차이에 대한 판정이다. README에도 주요 지원 제한은 공개되어 있다.

## 3. 주요 지적 사항

### F-01 / 높음 — VS2019·2022 확장 지원 미반영

- 요구: Role 프로젝트 1은 VS2017·2019·2022에서 사용할 확장을 명시한다.
- 사실: [소스 매니페스트](../src/VS2017.AIAssistant/source.extension.vsixmanifest#L10)와 실제 배포 ZIP의 설치 대상은 `Microsoft.VisualStudio.Community`, 버전 `[15.0.28307.0,16.0)` 하나다. VS2019/2022용 설치 대상·별도 패키지는 현재 릴리스에 없다.
- 영향: VS2019/2022가 PC에 설치되어 있거나 해당 MSBuild로 빌드 가능하다는 사실로 확장 설치 지원을 인정할 수 없다.
- 조치: 두 버전의 SDK·실행 환경에 맞는 패키지를 준비하고 각 IDE에서 설치, 창 열기, 요청, 적용·저장·취소를 검증해야 한다. 현재 README의 VS2017 한정 표기는 사실과 일치한다.

### F-02 / 보통 — 전체 검사의 일시 실패와 개별 재실행 성공

- 첫 전체 실행: **12/14묶음 통과, 종료 코드 1**. `editing`과 `experience`가 실패했다.
- 편집: **89/92**. [DialogChecks.cs](../tests/ux/DialogChecks.cs#L81)의 UX-09 설정 취소 복원, UX-11 저장 후 타 제공자 보존, UX-15 안내 표시 선택 보존이 실패했다. 이 실행의 합성 설정에는 `saved-new.exe`가 테스트가 기대한 Codex 경로 대신 Claude 경로에 남았다. 제공자 선택 실패·저장 경로 오류 등 원인은 이 관찰만으로 확정할 수 없다.
- 화면: **128개 통과 후 A 대화 닫기 검사에서 중단**. [DropdownExperienceChecks.cs](../tests/review/DropdownExperienceChecks.cs#L278)의 닫힘 상태/열린 대화 수 조건이 성립하지 않았다. 이후 검사는 실행되지 않았으므로 133개 전체 성공으로 집계하면 안 된다.
- 같은 VSIX로 각각 다시 실행: **편집 92/92, 화면 133/133 통과**, 각 종료 코드 0.
- 판정: 지속 재현되는 제품 결함으로 단정하지 않는다. 반대로 재실행 성공만으로 최초 실패를 삭제하거나 환경 문제로 확정하지도 않는다. 전체 실행의 안정성 확인은 보류한다.
- 조치: 제공자 전환 직후 실제 선택·내부 제공자·상태 메시지를 확인하고, 대화 저장/닫기의 실패 이유를 기록하도록 진단을 보강해 최초 실패 원인을 구분해야 한다. 이번 감사는 제품·기존 테스트를 수정하지 않았다.

### F-03 / 보통 — 라이선스 안내 배치의 달성 범위가 요구보다 좁음

- 요구: Role 기본 4는 Visual Studio의 라이선스 검증 관련 문구나 메시지가 나오지 않도록 하는 배치를 요청한다.
- 사실: [Build-Vsix.cmd](../scripts/Build-Vsix.cmd)는 IDE 대신 MSBuild를 호출한다. [BUILD_AND_LICENSE.md](../docs/BUILD_AND_LICENSE.md#L5)는 IDE 자체 로그인·라이선스 안내 해소와 구분하고, 로그인 후 안내 해소는 미검증이라고 명시한다.
- 판정: **배치 빌드에서 IDE 배너를 피하는 기능은 반영**, 실제 IDE의 안내가 해소됐다는 요구는 미검증이다.
- 조치: 적절한 계정 로그인·유효한 라이선스 상태에서 실제 IDE 안내가 해소되는지 확인한 결과를 별도로 남긴다. 현재 배치를 IDE 라이선스 안내 제거 완료로 보고하면 안 된다.

### F-04 / 보통 — `Chat` 제거 범위와 테스트 기준이 다름

- 요구: Role 추가 5는 상단의 `Chat` 단어 제거와 AI 선택 탭의 최상단 배치를 요청한다.
- 사실: WPF 본문에서는 제거됐지만 [AssistantToolWindow.cs:36](../src/VS2017.AIAssistant/ToolWindows/AssistantToolWindow.cs#L36)은 여전히 `Caption = "Chat"`이다.
- 검사 차이: 화면 검사는 컨트롤 내부 TextBlock만 검사한다. 반면 [IdeTests.cs:70](../tests/ide/IdeTests.cs#L70)은 IDE 탭 제목이 `Chat`이어야 통과한다.
- 판정: **본문에는 반영, IDE 탭 제목에는 미반영**이다. 요구가 본문 제목만 의미했다면 허용 가능하지만, 상단 전체 제거라는 해석으로는 완료가 아니다.
- 조치: 제거 대상에 IDE 탭 제목을 포함할지 요구 범위를 문서화하고 구현·IDE 검사 기준을 맞춘다.

### F-05 / 보통 — 실제 Claude·운영 연동의 검증 공백

- Claude의 모델/강도/Fast 인수 및 프로토콜은 fixture 검사로 확인한다. 실제 Claude 인증과 유료 Fast 요청 성공은 기존 최종 보고에서도 미검증이다.
- SQL Server는 스키마 읽기와 SQL 작성 요청 경로가 있다. 운영 DB 연결, 외부 SVN/TFVC 서버, 운영 배포 성공은 이번 감사와 기존 최종 검증 범위에서 확인되지 않았다.
- 판정: 코드 존재와 fixture 통과를 실제 계정·운영 연동 완료로 확대할 수 없다. 현재 README의 제한 고지는 적절하다.
- 조치: 지원을 확정할 실제 계정·테스트 서버의 통합 검증 결과를 별도로 남긴다. 실패 판정과 미검증 판정을 구분한다.

### F-06 / 보통 — 참고 계획의 선택 코드 전달은 후속 범위

- Role 프로젝트 1이 참조하는 [Project_Plan.md](Project_Plan.md#L773)의 MVP에는 코드20줄 선택 후 양쪽 AI에 질문하는 시나리오가 있다.
- 현재 [VisualStudioDocumentService.cs](../src/VS2017.AIAssistant/Services/VisualStudioDocumentService.cs#L213)의 Capture는 문서 시작부터 끝까지 읽는다. 선택 영역을 요청 컨텍스트로 따로 추출하지 않는다. 같은 파일의 TextSelection 사용은 소스 링크 이동 기능이다.
- 계획서 상단과 README는 전체 파일 전달 및 선택 코드 추출의 후속 범위를 공개하고 있다. 구현 제한을 숨긴 문제는 아니지만, 계획의 원래 선택 영역 시나리오까지 완료됐다고 판정할 수 없다.
- 계획서의 오래된 Phase 체크리스트에는 실제 존재하는 패키징·README·대화 기록도 미완료로 남아 있다. 현행 범위 설명과 단계별 완료 표시를 정리하면 다음 감사의 판정 혼선을 줄일 수 있다.

## 5. 요구 해석과 협업 관련 관찰

1. **Stack의 의미:** 현재 구현은 대화 이력을 누적하고 후속 요청에 최근 최대10메시지/24,000자 범위를 전달한다. [GenerateClicked](../src/VS2017.AIAssistant/Views/AssistantControl.xaml.cs#L97)는 busy이면 반환하고, [UpdateButtons](../src/VS2017.AIAssistant/Views/AssistantControl.xaml.cs#L327)는 요청 중 입력·전송·제공자/대화 전환을 잠근다. 따라서 ‘이전 답변 뒤 계속 질문’은 가능하지만 ‘응답 중 여러 요청을 쌓아 순서대로 처리’는 구현되지 않았다. Role의 Stack 문구만으로 후자가 필수라고 단정하지 않았으며 완료 범위를 명시해야 한다.
2. **제목 줄임 위치:** [AssistantControl.xaml:36](../src/VS2017.AIAssistant/Views/AssistantControl.xaml#L36)은 제목에 끝쪽 말줄임표를 사용한다. 가운데 줄임용 MiddleTitleConverter는 리소스로 선언됐지만 이 바인딩에는 연결되지 않는다. ‘중간 이후로 ...’가 폭 초과분 생략을 뜻하면 충족하나, 앞뒤를 남기는 정확한 가운데 줄임을 뜻하면 추가 조정이 필요하다.
3. **협업 중 배포:** WORK_STATUS에 이번 감사의 진행 중 등록은 **17:37:25**, 기존 TASK018 배포 완료 보고는 **17:37:44**로 남아 있다. TASK018의 배포 시작 공지는 감사 등록 전인 **17:36:20**이다. 완료 시각은 push 자체의 정확한 시각을 증명하지 않으므로 이 자료만으로 금지 규칙 위반을 단정하지 않는다. 다만 후속 보고 커밋에도 감사 진행 중 기록이 포함되어 있어 ‘다른 활성 작업 없음’의 확인 시점·예외 범위를 분명히 할 필요가 있다. 배포 전 최신 상태 재확인과 작업자별 기록의 선택적 커밋을 권고한다. CodexOrig2는 이 과정의 push를 실행하지 않았다.
