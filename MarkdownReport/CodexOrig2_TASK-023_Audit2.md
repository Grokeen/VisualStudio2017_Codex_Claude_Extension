## 4. 이번 감사의 지적 및 완료 조건

### R2-01 / 보통 — C6 패키지는 Claude 모델 정보만으로 로그인 상태를 확정함

**패키지에서 재현됐고, 현재 소스의 수정은 패키지에 아직 반영되지 않았다.**

1. 고정 패키지의 ProviderRuntimeService에 합성 Claude CLI의 모델 초기화 응답만 반환했다.
2. 로그인 요청·실제 계정 확인·추론 요청 없이도 결과가 **`Authenticated=true`**였다. 응답의 합성 모델은1개이고 계정 표시값은 `fixture-account`였다.
3. 최신 테스트의 `Claude model metadata alone never claims an authenticated account`가 두 번 모두 실패했다. 이 검사는 첫 실패에서 중단하므로 이후 native 검사들을 실행 완료로 집계하지 않았다.
4. 20:48 소스 사본의 [ProviderRuntimeService.cs](../src/VS2017.AIAssistant/Providers/ProviderRuntimeService.cs)는 해당 Claude 경로에 `info.Authenticated = null`과 별도 확인 안내를 이미 포함한다. 이 소스 변경만으로 C6 바이너리가 수정됐다고 판정할 수 없다.

이 인증 회귀는 C6의 기존46개 검사 이후 추가된 조건이다. 기존46/46 기록을 허위 또는 당시 실패로 소급하지 않는다. 이번에는 더 최신 검사와 C6 패키지의 차이가 드러난 것이다.

영향은 연결·로그인 상태를 잘못 안내하는 것이다. 이 재현만으로 계정 인증 우회나 실제 Claude 추론 성공을 주장하지 않는다.

**완료 조건:** 로그인 여부를 증명하지 않는 모델 메타데이터는 미확인으로 표시하고, 수정이 포함된 세 패키지를 다시 빌드한다. 해당 회귀가 세 버전의 새 DLL에서 통과하고 실제 CLI 로그인 검사와 모델 조회가 구분되는지 확인해야 한다.

### R2-02 / 보통 — PATH 밖의 설치된 CLI 자동 발견 누락

20:25 추가6의 자동 발견 요구를 고정 패키지에서 검사했다. 실제 CLI 실행·로그인 없이 실행 파일 해석 메서드만 호출했다.

| 설치 위치 | 실제 파일 존재 | PATH를 비운 자동 검색 | 같은 파일의 명시 경로 |
|---|---|---|---|
| `%USERPROFILE%/.local/bin/claude.exe` | 예 | **실패** | 성공 |
| `%LOCALAPPDATA%/Programs/OpenAI/Codex/bin/codex.exe` | 예 | **실패** | 성공 |

[CliEditProvider.ResolveExecutable](../src/VS2017.AIAssistant/Providers/CliEditProvider.cs)는 당시 명시 경로와 PATH만 검색했다. 설치돼 있어도 PATH에 등록되지 않은 일반적인 네이티브 설치 위치는 놓친다. 수동 경로 지정 기능은 정상이다. TASK022도 같은 누락을 별도 발견해 TASK020에 수정 요청한 기록이 있다.

**완료 조건:** 제공자별 알려진 네이티브 설치 후보를 제한된 범위로 검색하고, PATH 격리·실제 설치 위치·명시 경로 우선·발견 실패·스크립트 거부를 검증한다. 명시한 잘못된 경로를 다른 CLI로 조용히 대체하지 않아야 한다. 후속 소스 변경이 발생하더라도 이번 C6 검사 성공으로 소급하지 않는다.

### R2-03 / 보통 — 빌드 테스트가 PowerShell 오류 출력 줄바꿈에 따라 실패함

고정 사본의 `build-entry`는 두 실행 모두14/16개였다. 실패한 테스트는 다음 두 개다.

- `Wrong MSBuild file major version is rejected`
- `Batch preserves failure status and error output`

원본 결과를 확인하면 실제 종료 코드는 모두 기대한 **1**이다. 그러나 PowerShell이 긴 오류 앞부분을 출력하면서 `requires`를 `requi`/`res`로, `BUILD_FAILURE_SENTINEL`을 `BUILD_FAILUR`/`E_SENTINEL`로 줄바꿈했다. [Test-BuildEntry.ps1](../tests/build-entry/Test-BuildEntry.ps1)은 연속된 문자열만 찾으므로 실패한다. 공백을 제거하면 두 기대 문구가 모두 존재한다.

동일한 테스트·배치·Invoke-VsixBuild 세 파일의 해시를 확인한 뒤 원본 저장소 경로에서 재실행하면 **16/16 통과**했다. 따라서 이 결과를 제품의 MSBuild 오류 코드 전파 실패로 보고하지 않는다. 검사 경로·출력 모양에 의존하는 테스트 결함이다.

**완료 조건:** 오류 문구 검사를 자동 줄바꿈에 견디도록 정규화하거나 구조화된 오류로 확인한다. 종료 코드 검사는 유지하고 짧고 긴 경로에서 모두 재검사한다. 기존 실패 기록을 삭제하거나 기대 결과를 무조건 통과시키면 안 된다.

### R2-04 / 완료 판정 조건 — 최신 소스와 패키지를 다시 통합 검증해야 함

후보6의 기존 근거는 Role SHA `EC01FB7D…`와 소스55개에 대한 것이다. 이번 소스 사본63개·최신 Role에는 그 뒤의 변경이 있다. 특히 전체 스크롤, 외부 소스 변경 안내, 흰색 대화 목록, 진행 안내 중복/표시 위치, 자동 발견 및 추가된 우클릭 UI 요구를 후보6의 과거 성공 수치로 충족 처리할 수 없다.

감사 중 추가된 설치 시 필수 instruction도 기존의 사용자 편집용 공통 instruction과 구분해야 한다. 설치/첫 실행 시 생성과 일반 수정안·전체 액세스·협업 호출에 실제 전달되는지에 대한 새 검증 근거가 필요하다.

개발 중인 파일이 존재한다는 이유로 결함을 확정하지 않는다. 다만 **새 최종 후보의 소스 목록·각 DLL/VSIX 해시·Role 기준을 함께 고정하고**, 최신 테스트·실제 IDE 결과를 그 후보에 연결하기 전까지 전체 반영 완료로 보고하면 안 된다. 현재 협업 기록의 배포 보류는 이 조건에 부합한다.
