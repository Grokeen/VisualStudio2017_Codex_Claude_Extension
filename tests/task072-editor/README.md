# TASK072 editor contracts

Run with Windows PowerShell 5.1. The driver builds a private .NET 4.6.2 console fixture, creates no windows, and never starts Visual Studio, accesses an AI account or changes a user profile.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/task072-editor/Test-EditorEnhancements.ps1 -ReferenceManifest C:\private\sdk-references.json -AssemblyPath C:\candidate\Grokeen.VisualStudioThemes.dll -OutputDirectory C:\private\new-evidence
```

`OutputDirectory` must not exist. `AssemblyPath` loads and checks the exact supplied component DLL through reflection; its before/copy/after SHA-256 must match. When omitted, the current `EditorEnhancements.cs` is compiled into a private DLL first. All 125 contracts then invoke that DLL through the same reflection bridge. They include the original rules, ten readonly selected-theme storage cases, seventeen additional consumer-lifetime/format contracts, eight optional diff-overview scope contracts, and twenty-four guarded view-classification fallback contracts. Earlier singleton-identity assertions now require separate consumer facades while preserving one session-owned native subscription. The marker contract requires a pink one-pixel border with no specified background or fill, and the block format explicitly follows native `Comment` and `Priority.High`. `Diff/View/ShowDiffOverviewMargin` is enabled locally only when defined, preserves user changes, and restores the previous local/inherited state; old hosts without the option are untouched. A native view fallback is created only for an empty buffer-classification query. A shared per-view guard covers factory creation and the complete lazy native enumeration, and suppresses all own comment taggers during that query. Immediate native events are coalesced while own publications are excluded to prevent event cycles. The tests include factory/query exceptions, partial enumeration failure, creation and projection reentry, full native spans, native XML/string preservation, consumer isolation, and source cleanup on theme change/close. Native language-service inputs are narrow SDK interface fakes; successful contracts do not prove actual Roslyn, MEF composition, or IDE integration.

`ReferenceManifest` is JSON containing a `References` array of absolute DLL paths. The default points to the local research compile record in `artifacts/task072-research/primary-evidence/compile-baseline-3/compile-inputs.json`, which is not available in a fresh clone. Supply a manifest in a fresh environment. The driver never downloads dependencies automatically.

The reproducible reference set uses official Microsoft NuGet SDK packages: Text.Logic, Text.UI, Text.UI.Wpf, Text.Data and CoreUtility **15.6.27740**; Shell.15.0, Shell.Framework and Utilities **15.7.27703**; OLE.Interop **7.10.6071**, Shell.Interop.9.0 **9.0.30730**, Shell.Interop.10.0 **10.0.30320**. If Utilities is omitted from the supplied manifest, the driver adds its exact **15.7.27703/lib/net46** DLL from the current user's NuGet package cache and verifies the file exists. Add the .NET Framework 4.6.2 reference assemblies System, System.Core, WindowsBase, PresentationCore, PresentationFramework, System.Xaml and System.ComponentModel.Composition. A VS2017 Community MSBuild Roslyn compiler is the current compiler prerequisite. SDK references are copied only into private evidence, never shipped in the theme VSIX.

The result records every reference hash and fixture/source/DLL hashes. Preserved failed development runs identify fixture problems separately from product findings. Actual IDE checks are a separate reserved integration harness.
